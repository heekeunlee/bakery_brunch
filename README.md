# 🥐 빵집지도 — 전국 베이커리 · 브런치 카페

여행지 주변의 평판 좋은 베이커리 카페 · 브런치 카페 · 카페를 지도에서 찾는 웹앱.
매일 아침 자동으로 새 가게를 수집해 갱신됩니다.

**👉 https://heekeunlee.github.io/bakery_brunch/**

휴대폰 브라우저에서 열고 "홈 화면에 추가"를 누르면 앱처럼 쓸 수 있습니다 (PWA).
앱스토어 설치가 필요 없어서 지인에게는 링크만 보내면 됩니다.

---

## 어떻게 "평판"을 매기나

국내 지도 API 어디에도 평점·리뷰수는 공개되지 않습니다. 그래서 직접 만듭니다.

```
네이버 블로그 검색 → 상호 후보 추출 → 카카오 로컬 API 검증 → 스코어링
```

1. **수집** — 시군구별로 `베이커리카페 추천`, `브런치카페 추천` 등 4개 키워드로 블로그를 긁습니다.
   유사도순과 최신순을 섞어 신규 오픈 가게를 놓치지 않습니다.
2. **추출** — 제목과 해시태그에서 상호 후보를 **일부러 헐겁게** 뽑습니다.
   정밀도는 다음 단계에 맡깁니다.
3. **검증** — 후보를 카카오 로컬 API에 던져 ①카페/베이커리 카테고리 ②상호명 일치
   ③주소가 해당 시군구, 세 조건을 모두 만족할 때만 채택합니다.
   `내돈내산` 같은 노이즈는 카카오에 존재하지 않으므로 여기서 전부 사라집니다.
   좌표·전화번호·카카오맵 링크도 이 단계에서 함께 확보합니다.
4. **스코어링** — 서로 다른 블로그 포스트에서 몇 번 언급됐는지가 주 지표(75%),
   블로그 총 검색량이 보조 지표(25%)입니다.

> 총 검색량을 주 지표로 쓰지 않는 이유: 전국 체인이 자릿수로 다른 가게를 뭉갭니다.
> (테라로사 강릉 102,730건 vs 346커피스토리 7,574건) 로그 스케일과 상한 클리핑을
> 적용해도 편향이 남아서, 실제로는 **등장 빈도**가 훨씬 정직한 신호였습니다.

### 알려진 한계

- 상호 추출 재현율은 실측 **7/8**. 놓친 하나는 한 글자 상호(`곳`)로, 한 글자 후보를
  허용하면 노이즈가 폭증해 의도적으로 제외하고 있습니다.
- **메뉴·가격은 블로그 본문에서 뽑은 값**이라 절반 정도에만 붙습니다.
  메뉴판을 주는 API가 없어 "서로 다른 글 2편 이상이 같은 값을 말할 때"만 채택합니다.
- **스타벅스는 평판 랭킹에 넣지 않습니다.** 블로그 언급량으로 점수를 매기는 구조에서
  체인점은 언제나 상위를 독식합니다. 지도 위 별도 레이어(초록 핀)로만 켜고 끕니다.
- **사진은 네이버 이미지 검색 결과**입니다. 제목에 상호가 없으면 아예 붙이지 않지만,
  가게가 직접 올린 사진이 아니므로 앱에서도 출처를 밝혀 보여줍니다.
- **주차장·전기차 충전소는 가게 전용 시설이 아니라 주변 반경**(300m / 700m) 안에
  있는 곳의 수입니다. 카카오 장소 데이터에는 가게별 시설 정보가 없습니다.
- 블로그 상위 노출에는 **협찬글 편향**이 있습니다. 같은 블로거의 여러 글은 1회로만
  세어 완화하고 있지만 완전히 없앨 수는 없습니다.
- 영업시간 · 휴무일은 블로그 본문에서 정규식으로 추출한 값이라 **부정확할 수 있습니다.**
  앱에서도 "블로그 기준"이라고 표시하며, 방문 전 카카오맵 확인을 권합니다.

## 자동 갱신

워크플로 두 개가 요일을 나눠 돕니다. 같은 날 돌리면 네이버 검색 API 일일 한도를
둘이 나눠 쓰게 되어 양쪽 다 중간에서 끊깁니다.

| 워크플로 | 시각 | 하는 일 |
| --- | --- | --- |
| `daily-update.yml` | **목요일 06:00 KST** | 전국 시군구를 돌며 가게를 발굴한다 |
| `enrich.yml` | **월요일 06:00 KST** | 평판 상위 2,500곳에 사진·메뉴·후기·주변시설을 붙이고, 스타벅스 매장을 갱신한다 |

데이터가 실제로 바뀐 날에만 커밋하고 재배포합니다. 새로 발견된 가게는 앱에서
2주간 `NEW` 배지가 붙습니다.

특정 지역만 즉시 수집하고 싶으면 Actions 탭에서 `매주 목요일 자동 수집` →
`Run workflow` → 지역에 `강릉시` 입력.

> GitHub의 스케줄 워크플로는 저장소가 60일간 비활성이면 자동 중지됩니다.
> 커밋이 매일 쌓이므로 정상 동작 중에는 문제되지 않습니다.

## 설정

### 1. API 키 발급

| 키 | 발급처 | 용도 |
|---|---|---|
| `VITE_KAKAO_JS_KEY` | [카카오 디벨로퍼스](https://developers.kakao.com) → 앱 키 → JavaScript 키 | 브라우저 지도 렌더링 |
| `KAKAO_REST_KEY` | 같은 화면 → REST API 키 | 수집 스크립트의 장소 검증 |
| `NAVER_CLIENT_ID` / `NAVER_CLIENT_SECRET` | [네이버 개발자센터](https://developers.naver.com) → 검색 API 권한이 있는 기존 앱 | 블로그 수집 |

> ⚠️ **네이버 검색 API는 신규 등록이 막혀 있습니다.** 새 앱을 만들어 `사용 API`에
> `검색`을 추가하려 하면 "신규로 등록할 수 없는 API가 선택되었습니다"로 거부되고,
> 등록 드롭다운에도 `검색`이 아예 나타나지 않습니다. 차단 이전에 만들어둔 앱이
> 있다면 그 앱의 Client ID / Secret을 쓰세요 (앱 하나를 여러 용도로 써도 무방하며
> 쿼터만 공유됩니다). 이 프로젝트도 그렇게 동작 중입니다.
>
> 쓸 수 있는 기존 앱이 아예 없다면 카카오 검색 API(다음 검색)로 대체해야 하며,
> `scripts/lib/naver.mjs` 한 파일만 교체하면 되도록 인터페이스를 분리해 두었습니다.
> 다만 국내 카페 후기는 네이버 블로그에 몰려 있어 수집량 저하가 예상됩니다.

카카오 콘솔에서 두 가지를 반드시 해야 합니다. 하나라도 빠지면 지도가 뜨지 않습니다.

1. **`앱 → 플랫폼 키`** → `JavaScript 키` 카드의 `⋮` → 웹 도메인에
   `https://heekeunlee.github.io` 와 `http://localhost:5173` 등록
   (콘솔 개편으로 도메인이 키 단위로 등록되는 구조입니다)
2. **`제품 설정 → 카카오맵`** → 사용 설정 **ON**
   — 이걸 빼먹으면 REST 호출이 `disabled OPEN_MAP_AND_LOCAL service` 로 거부됩니다.
   이 토글 하나가 지도 렌더링과 로컬 API를 함께 엽니다.

> JavaScript 키는 브라우저에 노출되는 것이 정상입니다 — 그래서 도메인 제한이 유일한 방어선입니다.
> 반면 **REST API 키와 네이버 시크릿은 절대 프런트엔드로 넘기지 마세요.** 이 프로젝트가
> 백엔드 없이 빌드 타임 수집 구조를 택한 이유이기도 합니다.

### 2. GitHub Secrets 등록

저장소 → Settings → Secrets and variables → Actions → New repository secret

```
VITE_KAKAO_JS_KEY
KAKAO_REST_KEY
NAVER_CLIENT_ID
NAVER_CLIENT_SECRET
```

또는 CLI로:

```bash
gh secret set VITE_KAKAO_JS_KEY
gh secret set KAKAO_REST_KEY
gh secret set NAVER_CLIENT_ID
gh secret set NAVER_CLIENT_SECRET
```

### 3. 로컬 개발

```bash
cp .env.example .env.local   # 키 채우기
npm install
npm run dev
```

## 명령어

```bash
npm run dev                          # 개발 서버
npm run build                        # 프로덕션 빌드
npm run collect -- --region 강릉시    # 특정 지역만 수집
npm run collect -- --all             # 전국 (CI가 쓰는 방식)
npm run collect -- --missing         # 아직 한 곳도 못 건진 지역만
npm run collect -- --region 강릉시 --dry-run   # 저장하지 않고 결과만 확인
npm run enrich -- --limit 20 --dry-run         # 부가 정보 수집 미리보기
npm run enrich -- --top 2500                   # 평판 상위 2,500곳 (CI가 쓰는 방식)
npm run chains                                 # 전국 스타벅스 매장
node scripts/gen-icons.mjs           # PWA 아이콘 재생성
```

## 구조

```
data/regions.json          수집 대상 시군구
public/data/places.json    가게 목록 — 첫 화면이 바로 읽는다
public/data/details.json   사진·메뉴·후기·주변시설 — 지도를 그린 뒤 뒤에서 받아온다
public/data/chains.json    스타벅스 매장 — 레이어를 켤 때만 받아온다
scripts/
  run.mjs                  발굴 파이프라인 오케스트레이터
  enrich.mjs               부가 정보 수집
  chains.mjs               스타벅스 매장 수집 (사각형 재귀 분할)
  lib/naver.mjs            블로그·이미지 검색
  lib/kakao.mjs            장소 검증·보강, 주변 시설 조회
  lib/extract.mjs          상호 후보 추출, 태그·영업시간 파싱
  lib/enrich.mjs           메뉴·가격, 후기 선별, 아이동반·주차 판정
  lib/score.mjs            스코어링
src/                       React + 카카오맵 SDK 프런트엔드
```

백엔드도 데이터베이스도 없습니다. 수집은 CI에서 끝나고, 앱은 정적 JSON 하나만
읽습니다. 위시리스트와 내 평가는 **기기의 localStorage에만** 저장되며 어디로도 전송되지 않습니다.

전국 17개 시도 119개 시군구에서 5,563곳, 스타벅스 2,097곳이 수집되어 있습니다.

## 데이터 이용에 관하여

카카오 · 네이버 오픈 API의 검색 결과를 가공해 만든 개인용 비영리 프로젝트입니다.
각 사 오픈 API 이용약관을 확인하고 사용하세요. 상업적 재배포는 의도하지 않았습니다.
